# words-1.2 — Russian translations + full word-forms coverage (research)

**Date:** 2026-07-08
**Status:** research / pre-implementation
**Builds on:** `src/agent/prompts/words-1.1.ts` (see `docs/2026-06-27-agent-prompt-version-switching.md` for the version-registry mechanics)

## Goal

A new prompt version `words-1.2` that improves `words-1.1` in two ways:

1. **Russian translation during word introduction.** When introducing each item, the tutor
   translates the word/sentence into Russian and gives several Russian synonyms the item can map
   to (e.g. *ephemeral* → «мимолётный», «недолговечный», «эфемерный»), so the learner anchors
   the meaning to their L1.
2. **Exhaustive forms coverage.** The tutor names the grammatical form the item currently has
   (noun / verb / adjective / adverb / …) and walks through **all** the forms the word family
   takes: *decide* (verb) → *decision* (noun) → *decisive* (adjective) → *decisively* (adverb) →
   *undecided* (adjective, negated participle). For phrases/sentences: the structural variations
   the expression accepts.

This makes the agent **bilingual in output** (English lesson, Russian asides) while the session
itself stays an English lesson.

---

## 1. Where words-1.1 stands today

- The 1.1 prompt already has a `FORMS` thread, but it is shallow ("part of speech and its other
  forms") — 1.2 needs it to be *exhaustive and explicit*: name the current form first, then
  enumerate every member of the word family with its part-of-speech label.
- The 1.1 prompt **explicitly forbids other languages**: *"Teach entirely in English — no other
  language."* This line must be replaced in 1.2 with a controlled code-switching rule.
- The prompt enforces speech-shaped text (no lists/markdown). Russian must obey the same rule:
  Cyrillic words woven into flowing sentences, never read-out enumerations.

## 2. ElevenLabs multilingual facts (verified 2026-07-08)

> Doc paths: ElevenLabs recently moved ConvAI docs to `elevenlabs.io/docs/eleven-agents/...`;
> older `/docs/conversational-ai/...` links 404.

### 2.1 The critical blocker: the default TTS model is English-only

- Our agents bake `DEFAULT_TTS_MODEL = "eleven_flash_v2"` (`src/agent/prompts/index.ts`), which
  is also the ConvAI platform default — and it is **English-only**. With the current config,
  inline Cyrillic would be mangled / read with English phonetics.
- TTS models usable in ConvAI (`conversation_config.tts.model_id` enum) vs Russian support:

  | Model ID | Russian? | Notes |
  |---|---|---|
  | `eleven_flash_v2` | **no** | current default, ~75 ms, English-only |
  | `eleven_flash_v2_5` | **yes** (32 langs) | same ~75 ms latency; docs: "perfect for real-time voice agents"; numbers are not normalized by default (our prompt already writes numbers as words — OK) |
  | `eleven_turbo_v2` / `eleven_turbo_v2_5` | no / yes | both **deprecated** → use flash equivalents |
  | `eleven_multilingual_v2` | yes (29 langs) | highest quality, higher latency — not great for live conversation |
  | `eleven_v3_conversational` | yes (70+ langs) | "Expressive mode", audio tags; candidate for a later version |

- ~~Recommendation: `eleven_flash_v2_5`~~ **CORRECTION (found during implementation, 2026-07-08):**
  the create/update API **rejects `eleven_flash_v2_5` (and turbo v2.5) for English-primary agents**
  with `"English Agents must use turbo or flash v2"` — even when `language_presets` are configured.
  The platform reserves the flash/turbo v2.5 family for its own per-preset model switching, which
  doesn't help inline Cyrillic inside English turns. Verified by API probing:
  - `eleven_flash_v2_5` + `language: "en"` → **400**, with or without `language_presets.ru`
  - `eleven_flash_v2_5` + `language: "ru"` → accepted (not our shape — ASR must stay English)
  - `eleven_v3_conversational` + `language: "en"` → **accepted** ✅
  - `eleven_multilingual_v2` + `language: "en"` → accepted (higher latency)

  **Actual recommendation: `eleven_v3_conversational`** — multilingual (70+ langs incl. Russian),
  built for real-time agents, and accepted on an English-primary agent. `eleven_multilingual_v2`
  is the fallback if v3 misbehaves.
- Sources: <https://elevenlabs.io/docs/overview/models>,
  <https://elevenlabs.io/docs/eleven-agents/api-reference/agents/update>

### 2.2 Code-switching is a TTS capability, not an agent-language setting

Two distinct mechanisms exist, and it's important not to conflate them:

- **Inline code-switching (what we need).** Multilingual TTS models auto-detect the language of
  the text they synthesize, per passage. If the LLM writes «мимолётный» inside an English
  sentence and the model is `eleven_flash_v2_5`, it is pronounced as Russian. No agent-level
  language configuration is required. Short Russian snippets (a word or one sentence — exactly
  our use case) behave much better than long mixed passages.
- **`language_presets` + `language_detection` system tool (what we do NOT need).** These flip the
  *entire conversation state* (ASR language, voice, first message) to another language, e.g. for
  running the whole session in Russian. Language is otherwise fixed for the call. Not needed for
  1.2; only relevant if we later want a "session in Russian" mode. Side effect worth knowing:
  enabling additional languages auto-switches the platform to v2.5 multilingual models.
- Sources: <https://elevenlabs.io/docs/eleven-agents/customization/voice/customization/language>,
  <https://elevenlabs.io/docs/eleven-agents/customization/tools/system-tools/language-detection>

### 2.3 Voice choice matters

- The pinned teacher voice (`ELEVENLABS_TEACHER_VOICE_ID`) carries its identity across languages
  on multilingual models — but voices with strong English training bias leak English phonetics
  into Russian ("accent bleeding"; ElevenLabs help center acknowledges this failure mode).
- Mitigations, in order of effort:
  1. **Test the current voice** speaking the planned Russian snippets (quick TTS API check) — it
     may be perfectly acceptable for single words/short phrases.
  2. Pick a Voice Library voice verified for both English and Russian.
  3. **Multi-voice support** (`conversation_config.tts.supported_voices`): the documented
     *language-tutoring pattern*. Keeps the English default voice and lets the LLM switch to a
     native-Russian voice just for the translated span via inline markup
     (`<Russian>мимолётный</Russian>`). Requires extra agent config + prompt instructions —
     deferred to §5 improvements.
- Source: <https://elevenlabs.io/docs/eleven-agents/customization/voice/multi-voice-support>

### 2.4 ASR side (learner speaking Russian back)

- ConvAI ASR (`scribe_realtime` default) follows `agent.language` (`en`); there is no separate
  `asr.language` field. A learner *occasionally* saying a Russian word back will transcribe
  unreliably — mixed-language utterances are not documented as supported.
- Acceptable for 1.2: the prompt should keep learner interaction in English ("say it back in
  English", "use it in an English sentence") and treat garbled Russian echoes gracefully (the 1.1
  "didn't catch it → ask to repeat" rule already covers this).

## 3. Code changes required

Happily minimal — the registry already supports a per-version TTS model override
(`PromptVersion.ttsModelId`, hashed into the sync fingerprint, so the change triggers a PATCH).

### 3.1 Required (this is the whole list)

1. **New file `src/agent/prompts/words-1.2.ts`** with the 1.2 prompt (§4) and:
   ```ts
   const version: PromptVersion = {
     version: "words-1.2",
     label: "1.2 · + Russian translations, full word forms",
     prompt,
     ttsModelId: "eleven_v3_conversational", // Russian-capable; flash v2.5 is rejected for en agents
     additionalLanguages: ["ru"],
   };
   ```
2. **Register it** in `src/agent/prompts/index.ts` (`PROMPT_VERSIONS: [words10, words11, words12]`
   — last entry becomes the UI default).
3. **Run `pnpm sync:agents:plan`**, then `pnpm sync:agents`, commit `agents.lock.json`.

Small registry/sync extension (added during implementation): `PromptVersion.additionalLanguages`
(→ `conversation_config.language_presets` in `sync-agents.ts` `agentBody()`, included in the sync
hash). words-1.2 declares `["ru"]` — not required for inline Cyrillic (v3 handles that from the
text alone), but it keeps the door open for a future learner-side Russian session mode. No changes
in `agent-registry.ts`, the lesson UI, or the DB — the version picker and lockfile flow pick the
new version up automatically.

### 3.2 Not required (explicitly)

- No `language_detection` system tool — session stays English-primary (§2.2).
- No `agent.language` change — stays `"en"` (drives ASR correctly for the English-speaking flow).
- No client SDK changes — inline Cyrillic arrives as normal agent text; subtitles/transcript
  (`onMessage`) render it as-is.

### 3.3 One pre-flight check

Verify the pinned teacher voice speaks acceptable Russian **before** syncing, e.g.:

```bash
curl -s -X POST "https://api.elevenlabs.io/v1/text-to-speech/$ELEVENLABS_TEACHER_VOICE_ID" \
  -H "xi-api-key: $ELEVENLABS_API_KEY" -H "content-type: application/json" \
  -d '{"model_id":"eleven_flash_v2_5","text":"Ephemeral — по-русски это мимолётный, недолговечный или эфемерный."}' \
  -o /tmp/ru-voice-check.mp3
```

If the accent is unacceptable, swap the voice (or adopt multi-voice, §5.1).

## 4. Prompt design for words-1.2

Delta against 1.1 (everything else carries over: proactivity, interruptions, recycle/recap,
speech-shaped output, SOUND thread):

1. **Replace the monolingual rule.** Drop *"Teach entirely in English — no other language"* and
   replace with a controlled code-switching rule, e.g.:

   > Teach in English. The ONLY place you use Russian is the translation moment inside each
   > item's introduction: give the Russian translation and two or three Russian synonyms it can
   > map to, spoken naturally in Russian. Everything else — examples, questions, chit-chat —
   > stays in English, and you never switch the whole conversation to Russian even if asked;
   > instead offer the translation and return to English.

2. **New thread inside the per-item weave** (joining MEANING / FORMS / USAGE / SOUND):

   > TRANSLATION — right after the meaning lands, give the Russian: "in Russian you'd say
   > мимолётный — or, depending on the shade, недолговечный or эфемерный", and in one short
   > phrase note when each Russian synonym fits (register/nuance), so the learner hears WHICH
   > Russian word matches WHICH shade of the English one. For a phrase or sentence, give the
   > natural Russian equivalent (how a Russian speaker would actually say it), not a word-by-word
   > gloss, plus one alternative phrasing.

3. **Deepen FORMS** from "part of speech and its other forms" to:

   > FORMS — first name the form the item has right now ("as listed, it's an adjective"), then
   > walk the whole word family aloud, naming each member's part of speech: the noun, the verb,
   > the adjective, the adverb, common negated or prefixed relatives — and flag which family
   > members are common and which are rare or don't exist ("there's no adverb for this one — say
   > 'in a … way' instead"). Reuse the stress-shift trap from SOUND when a form moves the stress.
   > For a phrase/sentence: how it inflects in use — tense, person, polite vs blunt variants,
   > which slots are swappable.

4. **Speech-shape the Russian too.** Extend the TTS-hygiene block: Russian words are written in
   Cyrillic (never transliterated — Latin transliteration would be pronounced as English), woven
   into the sentence, and kept short — a word or one short phrase at a time, never a long Russian
   passage.

5. **Recap stays English-first** but may use Russian as a prompt: "what was the English word for
   мимолётный?" — a cheap RU→EN recall exercise that reuses the translations.

Doc-comment header of `words-1.2.ts` should summarize this delta (matching the style of 1.1's
header).

## 5. Possible improvements (backlog, not in 1.2)

1. **Multi-voice Russian (native pronunciation).** Add
   `tts.supported_voices: [{label: "Russian", voice_id: <ru_voice>, language: "ru", ...}]` and
   teach the prompt to wrap Russian in the voice tag. Documented by ElevenLabs specifically as
   the language-tutoring pattern. Needs: `PromptVersion.supportedVoices?` in `types.ts`,
   `agentBody()` + `hashConfig()` extension in `sync-agents.ts`, a second env var
   (`ELEVENLABS_RU_VOICE_ID`). Do this if §3.3 shows the teacher voice's Russian is weak.
2. **Learner L1 as a dynamic variable.** Replace hard-coded Russian with `{{native_language}}`
   (like `{{items_list}}`), passed per session from the lesson page — one agent serves any L1.
   Needs a small UI field + overrides in the session kickoff; prompt says "the learner's native
   language is {{native_language}}".
3. **Curated translations over on-the-fly LLM translation.** Store per-item Russian translations
   and synonyms in the lesson items (Supabase column / JSON), inject them into `{{items_list}}`.
   Removes translation-hallucination risk for rare senses; the agent then *presents* rather than
   *invents* the mapping. Could be pre-generated once by the LangChain/Claude pipeline
   (`src/lib/llm.ts`) at lesson-creation time and edited by the user.
4. **Translation-quality eval.** Post-call webhook → LangSmith (see
   `docs/2026-06-28-langsmith-tracing-observability.md`): an LLM-as-judge checks each session's
   Russian translations for accuracy/synonym quality — regression signal for future prompt bumps.
5. **"Session in Russian" accessibility mode.** For lower-level learners: `language_presets.ru` +
   the `language_detection` system tool so a learner who answers in Russian flips the whole
   session (ASR included). Deliberately out of scope for B2–C1.
6. **`eleven_v3_conversational` trial.** 70+ languages and expressive audio tags (whispering,
   emphasis) — could make the SOUND thread noticeably better; needs latency/cost evaluation
   against flash v2.5.
7. **RU→EN production drills.** Beyond the recap: a mid-lesson micro-drill where the tutor says a
   Russian synonym and the learner must produce the English item in a sentence — strengthens the
   active-recall direction that actually matters for speaking.

## 6. Risks & open questions

- **Accent bleeding** (§2.3): the single biggest quality risk; mitigated by the §3.3 pre-flight
  and, if needed, backlog item 5.1. Short snippets are the well-behaved case.
- **Translation accuracy**: the LLM (claude-sonnet-4-6) translates on the fly; generally strong
  for common vocabulary, riskier for idioms' register nuances. Backlog item 5.3 is the durable
  fix; the 1.2 prompt's existing "don't invent meanings — say so if unsure" rule applies to
  Russian too (worth restating in the TRANSLATION thread).
- **ASR of Russian learner speech** (§2.4): learner-side Russian is unreliable with `agent.language: en`;
  the prompt keeps learner production in English by design.
- **Transcript rendering**: Cyrillic flows through `onMessage` subtitles/history as plain text —
  no known issue, but worth one visual check in the lesson UI on first live session.
